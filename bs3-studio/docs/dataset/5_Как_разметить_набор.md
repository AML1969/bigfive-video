# Как разметить набор роликов для обучения

Документ — для того, кто превращает собранные материалы в набор для обучения: владельца проекта, организатора сбора или разработчика. Он стоит между сбором (документы 0–3) и обучением ([документ 4](4_Как_обучить_AMLAI_2.0.md)): на входе — ролики, паспорта, самооценки и бланки наблюдателей, на выходе — таблица меток `labels.csv` и папка, которую можно отдать разработчику.

**Что здесь называется разметкой.** Никто не смотрит ролики заново и не рисует в них рамки. Метки уже собраны — это ответы наблюдателей и участников в бланках. Разметка — это превратить ответы в числа по единым правилам, отбросить негодные, посчитать по каждому ролику среднее и записать всё так, чтобы код обучения прочитал таблицу без вопросов. Правила подсчёта и проверок заданы в [памятке организатору](0_Памятка_организатору.md) (разделы 7–10); здесь они собраны в порядок действий и доведены до точных порогов.

## Коротко о главном

1. Выгрузите формы в `self.csv` и `ratings.csv`, а `videos.csv` заполните по паспортам и приёмке — три таблицы памятки. Приведите коды к одному виду, уберите дубли.
2. Сверьте таблицы между собой и с папкой копий: у каждого принятого ролика есть паспорт, самооценка и не меньше двух оценок.
3. Посчитайте баллы: перекодировка обратных строк, балл черты, перевод в шкалу 0…1.
4. Решите, какие оценки действительны: уберите оценки с помехами и знакомством, пометьте небрежные, исключите небрежных наблюдателей.
5. По каждому ролику — среднее действительных оценок, их число и разброс. Самооценка — отдельными столбцами.
6. Посчитайте надёжность меток и посмотрите на распределения.
7. Разделите ролики на тест и пять частей — один раз, по людям, с записанным начальным числом.
8. Соберите папку набора, напишите паспорт набора, зафиксируйте версию.

Начинайте с пробного набора (памятка, раздел 11): на 20–30 роликах видны все ошибки выгрузки, а исправить их ещё дёшево.

## 1. Что такое метка в этом наборе

| Что | Откуда | Роль |
| --- | --- | --- |
| Пять черт по впечатлению | карта из десяти шкал в бланках наблюдателей, среднее по ролику | **основная метка**: модель учится впечатлению, как AMLAI 1.0 |
| «Пригласил бы на собеседование» | вопрос в бланке наблюдателя, среднее по ролику | основная метка шестого выхода |
| Пять черт по самооценке | 50 утверждений (и карта) в самооценке участника | дополнительная метка, для анализа |
| Кластер, пол, возраст, устройство | паспорт ролика и список организатора | для разбиения и анализа ошибок, не для обучения |

Чего размечать не нужно: эмоции, голос, мимику, манеру речи и тип MBTI. Их продукт считает готовыми моделями и формулой — меток для них нет. Отрезки по 20 секунд размечать тоже не нужно: метка одна на ролик, все его отрезки её наследуют (документ 4, раздел 4). Если наблюдатели смотрели трёхминутный отрывок, а не ролик целиком (памятка, раздел 6), метка всё равно относится ко всему ролику.

Две мишени — впечатление и самооценка — хранятся в разных столбцах и никогда не усредняются между собой (памятка, раздел 1).

Список «код — студент» в набор не входит и разработчику не передаётся: он нужен только организатору, чтобы разобрать спорные коды. Всё остальное идёт в работу.

Если роликам ещё не хватает оценок (памятка, разделы 5 и 7), сначала доберите их: разметка делается по окончательным данным. Набор, размеченный до добора, придётся переделывать — и менять в нём можно не всё (раздел 10).

## 3. Из форм в таблицы

Три таблицы описаны в памятке, раздел 10: `videos.csv` (ролик и приёмка), `self.csv` (самооценка), `ratings.csv` (оценки наблюдателей). Там же — все столбцы. Здесь — как их получить из форм без ошибок.

**Выгрузка.** Сохраните выгрузку формы как есть в папку `raw` вне папки набора (выгрузок с адресами почты в наборе быть не должно — раздел 10) и больше её не трогайте; работайте с копией. Столбцы, которых нет в памятке, — адрес почты, имя аккаунта и прочие служебные столбцы формы — из копии сразу удалите. Остальные заголовки — это тексты вопросов; переименуйте их в короткие имена памятки: коды — `code` в самооценке, `rater` и `video` в бланке наблюдателя; ответы по карте — `s01` … `s10` в порядке строк карты, 50 утверждений — `q01` … `q50` в порядке документа 2, вопрос о собеседовании — `interview`, остальные — `known`, `glasses`, `beard`, `confidence`, `noise`, `comment`. Отметка времени формы — в столбец `date`. Даты везде пишите как `ГГГГ-ММ-ДД` (при необходимости `ГГГГ-ММ-ДД ЧЧ:ММ`): так они сортируются как текст, и «последняя» запись находится без ошибок.

**Ответы — числами.** Если форма выгружает ответ словами («7 — полностью подходит правое»), оставьте только число. Варианты ответов на остальные вопросы храните ровно теми словами, что в бланке: `нет`, `да`, `плохой звук` — иначе проверки ниже их не узнают.

**`videos.csv` — не выгрузка.** Её заполняете вы при приёмке по паспортам (документ 1, раздел 10; памятка, разделы 3 и 10). Ответы «да / нет» и `status` пишите ровно как в памятке: `да`, `нет`; `принят`, `пересъёмка`, `отклонён` — строчными, без пробелов и точек. По `glasses` и `beard` сверяются ответы наблюдателей (`flag_attn`, раздел 6), по `status` отбираются принятые ролики: опечатка здесь помечает все оценки ролика или выбрасывает его из набора.

**Коды.** Самая частая ошибка — код написан не так, как выдан: строчной буквой, с пробелом, русской буквой «Р» вместо латинской `R` (на экране они неотличимы). Приведите все коды к виду `R` плюс четыре цифры: заглавная латинская буква, без пробелов. Код, который после этого не подходит под образец или которого нет в списке организатора, не исправляйте наугад — выясните у организатора по дате и содержанию ответа и запишите исправление в `exclusions.csv` (раздел 4): как было написано, на что заменили и почему.

**Дубли.** Участник заполнил самооценку дважды — оставьте последнюю полную. Один наблюдатель дважды оценил один ролик — оставьте последнюю оценку. Наблюдатель оценил собственный ролик — оценку уберите. Строки, убранные на этом шаге, перечислите в `exclusions.csv` (раздел 7): код наблюдателя, код ролика, причина. Правило «ничего не удалять» из раздела 6 относится к оценкам, прошедшим этот шаг.

**Кодировка и имена.** Файлы — CSV в UTF-8, разделитель — запятая, имена столбцов — латиницей. Ответы храните такими, какими их дали: перекодировка — только при подсчёте (раздел 5), пометки проверок — отдельными столбцами справа.

Таблицы готовы, когда:

- [ ] все коды подходят под образец и есть в списке организатора;
- [ ] в `ratings.csv` нет пар «наблюдатель — ролик», встречающихся дважды, и нет оценок собственного ролика;
- [ ] в `self.csv` по одной строке на участника;
- [ ] ответы по шкалам — числа в своих пределах: карта 1–7, утверждения 1–5, собеседование 1–7, уверенность 1–3;
- [ ] в `videos.csv` ответы «да / нет» и `status` написаны одинаково, как в памятке.

## 4. Сверка таблиц и папки

| Проверка | Если не сходится |
| --- | --- |
| У каждого ролика со статусом «принят» есть файл `work/<код>.mp4` | копии нет — сделайте по памятке, раздел 4; файл есть, а строки нет — ролик не прошёл приёмку, в набор не идёт |
| У каждого принятого ролика есть паспорт (строка `videos.csv` заполнена) | запросите у участника; без паспорта не работает проверка внимательности (раздел 6) |
| У каждого принятого ролика есть самооценка | запросите; ролик без самооценки в обучение идёт, в анализ связи с самооценкой — нет |
| У каждого принятого ролика не меньше двух оценок | доберите (памятка, раздел 5); иначе ролик выпадает (раздел 6) |
| Каждая оценка относится к принятому ролику | оценка непринятого ролика в набор не идёт, но её сохраните: при пересъёмке она недействительна, запись другая |
| Каждая пара «наблюдатель — ролик» есть в таблице назначений | оценка ролика, который наблюдателю не назначали, — повод спросить, как он его увидел |

Все несовпадения и исправления кодов записывайте в `exclusions.csv`: код, что не сошлось, что сделали.

## 5. Подсчёт баллов

Правила — из памятки, раздел 9; здесь они повторены, чтобы считать по одному документу.

**Карта из десяти шкал** (одинакова у наблюдателей и в самооценке; ответы 1–7):

| Черта | Прямая строка | Обратная строка |
| --- | --- | --- |
| Экстраверсия | 1 | 6 |
| Доброжелательность | 7 | 2 |
| Добросовестность | 3 | 8 |
| Эмоциональная устойчивость | 9 | 4 |
| Открытость | 5 | 10 |

1. Обратная строка: 8 минус ответ.
2. Балл черты: среднее двух строк, от 1 до 7.
3. В шкалу 0…1: (балл − 1) / 6.

Пример: строка 1 — ответ 6, строка 6 — ответ 3. Перекодируем строку 6: 8 − 3 = 5. Экстраверсия: (6 + 5) / 2 = 5,5; в шкале 0…1 — (5,5 − 1) / 6 = 0,75.

**50 утверждений** (только самооценка; ответы 1–5):

| Черта | Прямые | Обратные |
| --- | --- | --- |
| Экстраверсия | 1, 11, 21, 31, 41 | 6, 16, 26, 36, 46 |
| Доброжелательность | 7, 17, 27, 37, 42, 47 | 2, 12, 22, 32 |
| Добросовестность | 3, 13, 23, 33, 43, 48 | 8, 18, 28, 38 |
| Эмоциональная устойчивость | 9, 19 | 4, 14, 24, 29, 34, 39, 44, 49 |
| Открытость | 5, 15, 25, 35, 40, 45, 50 | 10, 20, 30 |

1. Обратное утверждение: 6 минус ответ.
2. Балл черты: среднее десяти утверждений, от 1 до 5.
3. В шкалу 0…1: (балл − 1) / 4.

**Вопрос о собеседовании:** ответ 1–7, в шкалу 0…1 — (ответ − 1) / 6.

**Пропуски.** В бланке наблюдателя все десять строк карты и вопрос о собеседовании обязательны: оценка хотя бы с одним пропуском неполная и в расчёт не идёт. Обязательными в форме эти вопросы делайте только с переходом после вопроса «Знаком ли вам этот человек?»: при ответе не «нет» форма завершается без карты. Иначе наблюдатель, узнавший человека (документ 3), не сможет сдать бланк или заполнит карту наугад. Случай «ролик не открылся» отмечается уже после карты, поэтому обязательные строки помешают и ему — такой наблюдатель пишет организатору, как велит документ 3. Если переход в форме сделать нельзя — оставьте строки необязательными: неполные оценки отсеет это правило. В 50 утверждениях допустимо до двух пропусков на черту — балл считается по оставшимся; при трёх и больше балл черты не ставится. Пропуск — это пустая ячейка, а не ответ «посередине» (4 в карте, 3 в утверждениях).

Эмоциональная устойчивость и в карте, и в утверждениях направлена одинаково: больше — спокойнее. Ничего переворачивать не нужно.

## 6. Какие оценки действительны

Порядок важен: сначала убираются негодные оценки, потом решается судьба наблюдателей, и только потом считаются средние.

1. **Неполные оценки** (раздел 5) — недействительны.
2. **Помехи или знакомство.** Ответ на «Знаком ли вам этот человек?» не «нет» или ответ на «Были ли помехи?» не «нет» — оценка недействительна. Наблюдателю выдаётся запасной ролик (памятка, раздел 8).
3. **Пометки небрежности** — оценка остаётся действительной, но получает отметку:

| Пометка | Когда ставится |
| --- | --- |
| `flag_same` | во всех десяти строках карты одно и то же число |
| `flag_contra` | после перекодировки две строки одной черты расходятся на 4 балла и больше — и так в двух чертах или больше |
| `flag_attn` | ответ про очки или про бороду не совпал с паспортом ролика (паспорт сверен с записью при приёмке, поэтому он и есть истина) |

4. **Наблюдатель целиком.** По действительным оценкам каждого наблюдателя посчитайте три признака: доля помеченных оценок больше 30%; стандартное отклонение всех его ответов по карте меньше 0,5 балла; его баллы черт не связаны положительно со средними баллами других наблюдателей тех же роликов (одна корреляция по всем парам «ролик × черта», причём из баллов каждой черты заранее вычтено её среднее по всем действительным оценкам — иначе разные средние уровни черт дадут положительную связь даже тому, кто ставит всем роликам один и тот же профиль; корреляция не выше нуля; считается, когда у наблюдателя не меньше четырёх роликов, у которых есть и другие оценки). Два признака из трёх — все оценки наблюдателя становятся недействительными, а его ролики идут на добор. Это ровно правило памятки, раздел 8, с порогом для третьего признака.
5. **Две оценки с большим расхождением** (памятка, раздел 7) — повод добрать третью и четвёртую, а не выбрасывать одну из двух. Ни одна действительная оценка не удаляется за расхождение с другими. Пороги памятки даны в баллах 1–7; в шкале 0…1 это: 4 балла — 0,67, 3 балла — 0,50, стандартное отклонение 2 балла — `sd_` не меньше 0,33 (при двух оценках это половина их разницы).
6. **Ролик, у которого меньше двух действительных оценок,** в набор не идёт — ни в обучение, ни в тест. Запишите его в `exclusions.csv`: при доборе он вернётся.

Ничего не удаляйте из таблиц. Каждая оценка получает столбцы `valid` (да/нет), `reason` (почему нет) и три столбца пометок — так любое решение можно проверить и отменить.

## 7. Метка ролика

По каждому ролику с двумя и больше действительными оценками:

- пять черт и собеседование — простое среднее действительных оценок в шкале 0…1 (поправку на строгость наблюдателя не делайте: при 2–5 роликах на наблюдателя она невозможна — нужно около десяти, памятка, раздел 9);
- `n_ratings` — число действительных оценок;
- `sd_<черта>` — разброс между наблюдателями (стандартное отклонение с делением на число оценок n, а не на n − 1);
- `self_<черта>` — самооценка по 50 утверждениям, 0…1; пусто, если самооценки нет или балл не поставлен;
- `cluster` — из `videos.csv`.

Имена столбцов черт — как в First Impressions V2 (`openness`, `conscientiousness`, `extraversion`, `agreeableness`, `non-neuroticism`): так таблицу читает код обучения. Полный состав `labels.csv` — в документе 4, раздел 2.

Рядом с `labels.csv` сохраните:

| Файл | Что в нём |
| --- | --- |
| `ratings_scored.csv` | каждая оценка: исходные ответы, баллы черт 0…1, пометки, `valid`, `reason` |
| `self_scored.csv` | самооценка: баллы по 50 утверждениям и по карте, 0…1 |
| `raters.csv` | по каждому наблюдателю: число оценок, доля пометок, разброс, связь с другими, исключён ли |
| `exclusions.csv` | что и почему не вошло: ролики, оценки, наблюдатели |

## 8. Надёжность меток и здравый смысл

До разбиения и обучения посчитайте и запишите в `checks.md`:

**Надёжность.** Внутриклассовая корреляция по однофакторной модели — она подходит для схемы, где у каждого ролика свои наблюдатели и их число разное. Для каждой черты и для собеседования по действительным оценкам размеченных роликов:

- ICC(1) — надёжность одной оценки;
- ICC(1,k) — надёжность средней оценки ролика, то есть самой метки;
- потолок модели — корень из ICC(1,k): сильнее этого модель с меткой коррелировать не может (памятка, раздел 9).

Формула — в коде раздела 11. Чего ждать при двух оценках на ролик: по экстраверсии ICC(1,k) около 0,6, по остальным чертам — 0,2–0,5 (памятка, раздел 6). Чтобы понять, сколько оценок на ролик доведёт надёжность до 0,8, подставьте ICC(1) в формулу Спирмена — Брауна: надёжность k оценок = k·ICC(1) / (1 + (k − 1)·ICC(1)).

**Связь с самооценкой.** Корреляция средней оценки наблюдателей с самооценкой по каждой черте. Ожидайте 0,1–0,3 (памятка, раздел 9); выше всего по экстраверсии (памятка, раздел 1). Корреляция около нуля по всем чертам — повод перепроверить ключи и порядок столбцов.

**Распределения.** По каждой черте — среднее, разброс и гистограмма меток. Метки обычно теснятся к середине (0,4–0,7); это нормально. Тревожно, когда разброс метки меньше 0,08 или больше 80% роликов лежат по одну сторону от 0,5: модели почти нечему учиться, а в продукте тип MBTI по этой оси почти у всех будет одним и тем же или «X»: граница — 0,5, а оценки от 0,35 до 0,65 продукт считает пограничными и ставит «X» (документ 4, раздел 8).

**50 утверждений.** Согласованность утверждений одной черты — альфа Кронбаха; в оригинале 0,79–0,87. Утверждение, которое идёт против своей шкалы, — признак неудачного перевода (памятка, раздел 11).

**Наблюдатели.** Сколько исключено и почему; у скольких роликов меньше трёх оценок.

## 9. Разбиение

Правила — в документе 4, раздел 3; здесь — порядок.

1. Единица разбиения — человек. Все отрезки ролика наследуют его часть; если у человека два принятых ролика, оба идут в одну часть.
2. Тест — 15–20% роликов: столбец `split` со значением `test`, у остальных — `train`. Если кластеров знакомства шесть и больше и они примерно равны, в тест и в части идут целые кластеры: в тест — один кластер или несколько, ближайшие к 15–20%; остальных должно остаться не меньше пяти, они раскладываются по пяти частям. Если кластеров меньше шести — отдельные люди, случайно.
3. Запишите начальное число генератора в `checks.md` и в паспорт набора: разбиение должно воспроизводиться.
4. Остальные ролики — пять частей примерно поровну: столбец `fold` от 1 до 5. У тестовых роликов `fold` пустой.
5. Разбиение делается один раз. Никакие проверки, подбор параметров и калибровка не должны касаться тестовых роликов до теста (документ 4, раздел 8).

## 10. Папка набора и передача

Соберите папку с версией в имени, например `ru_set_v1`:

| Что | Содержимое |
| --- | --- |
| `work/` | копии роликов из `labels.csv` без начала с листом, имена — коды; копии исключённых роликов (раздел 6) в набор не кладите |
| `labels.csv` | метки, по строке на ролик (документ 4, раздел 2) |
| `videos.csv`, `self.csv`, `ratings.csv` | исходные таблицы после раздела 3 |
| `ratings_scored.csv`, `self_scored.csv`, `raters.csv`, `exclusions.csv` | результаты разделов 6–7 |
| `checks.md` | надёжность, распределения, начальное число, исключения (раздел 8) |
| `README.md` | паспорт набора (ниже) |
| `SHA256SUMS` | контрольные суммы всех таблиц (`sha256sum *.csv > SHA256SUMS`) |

Чего в папке быть не должно: оригиналов (они лежат отдельно, как архив), списка «код — студент», выгрузок форм с адресами почты и фамилиями, таблицы назначений с именами. Столбцы со свободным текстом просмотрите: `comment` в `ratings.csv` (наблюдатели иногда пишут имена) и `problems` в `videos.csv` (участник мог написать, чью фамилию или какой вуз назвал — памятка, раздел 2). Такие слова уберите. В `file` проверьте, что имя исходного файла — не фамилия. В `exclusions.csv` и `checks.md` называйте людей только кодами. Передавайте папку на внешнем диске (копии роликов — сотни гигабайт) или по закрытой ссылке, открытой только разработчику, и закройте ссылку после скачивания; не через мессенджеры и не через общую папку сбора. После копирования разработчик сверяет `SHA256SUMS`. Папка целиком — персональные данные: ролики с лицами и речью; храните её на компьютере проекта и в git не кладите (документ 4, раздел 9).

**Паспорт набора** (`README.md`): дата сбора и разметки; сколько роликов получено, принято, размечено, в тесте; состав участников по полу, возрасту и кластерам; сколько оценок на ролик (минимум, среднее); ролик целиком или отрывок; надёжность по чертам и потолок; что исключено и почему; версия документов 1–3, по которым собирали; кто и когда разметил.

**Версии.** После передачи ничего в папке не меняйте. Пришли добранные оценки или новые ролики — делайте `ru_set_v2` рядом и записывайте в её `README.md`, что изменилось. Два правила для новой версии: столбцы `split` и `fold` у старых роликов не меняются, иначе тестовые ролики попадут в обучение; новые ролики распределяются так: если набор делили по кластерам, новый ролик идёт туда, где уже лежит его кластер (новый кластер — случайно и целиком), если по людям — случайно, в тех же долях. Для этого скрипт разметки для `ru_set_v2` получает `labels.csv` первой версии: у старых роликов `split` и `fold` берутся из него, распределяются только новые. Без этого файла разбиение пересчитается заново — с тем же начальным числом, но по другому списку роликов. Новое начальное число запишите в `checks.md`.

## 11. Код

Правила разделов 3–9 реализованы в `training/ru_labels.py` (документ 4, раздел 4). Запуск из `bs3-studio`: `~/bs/venv/bin/python -m training.ru_labels --set <папка набора>`; для новой версии набора — ещё `--prev <labels.csv прежней версии>`. Скрипт пишет все файлы раздела 10, кроме `README.md` и `SHA256SUMS`, и готовый `labels.csv` не перезаписывает. Проверен он на искусственном наборе (`tests/test_ru_labels.py`). Три его главные функции:

```python
import numpy as np
import pandas as pd

TRAITS = ["openness", "conscientiousness", "extraversion",
          "agreeableness", "non-neuroticism"]
# карта: черта -> (прямая строка, обратная строка); ответы 1..7
CARD = {"extraversion": (1, 6), "agreeableness": (7, 2),
        "conscientiousness": (3, 8), "non-neuroticism": (9, 4),
        "openness": (5, 10)}
# 50 утверждений: черта -> (прямые, обратные); ответы 1..5
IPIP = {
    "extraversion": ([1, 11, 21, 31, 41], [6, 16, 26, 36, 46]),
    "agreeableness": ([7, 17, 27, 37, 42, 47], [2, 12, 22, 32]),
    "conscientiousness": ([3, 13, 23, 33, 43, 48], [8, 18, 28, 38]),
    "non-neuroticism": ([9, 19], [4, 14, 24, 29, 34, 39, 44, 49]),
    "openness": ([5, 15, 25, 35, 40, 45, 50], [10, 20, 30]),
}


def score_card(row):
    """Пять баллов 0..1 по строкам s01..s10 одной оценки."""
    out = {}
    for t, (d, r) in CARD.items():
        a, b = row[f"s{d:02d}"], 8 - row[f"s{r:02d}"]
        out[t] = ((a + b) / 2 - 1) / 6
    return out


def score_ipip(row, max_missing=2):
    """Пять баллов 0..1 по q01..q50; при >2 пропусках черта пустая."""
    out = {}
    for t, (d, r) in IPIP.items():
        vals = [row[f"q{i:02d}"] for i in d]
        vals += [6 - row[f"q{i:02d}"] for i in r]
        vals = pd.Series(vals, dtype="float")
        if vals.isna().sum() > max_missing:
            out[t] = np.nan
        else:
            out[t] = (vals.mean() - 1) / 4
    return out


def icc_oneway(long, target="video", value="extraversion"):
    """ICC однофакторной модели для роликов с разным числом оценок:
    icc1 - одной оценки, icc1k - средней по ролику (самой метки)."""
    g = long.groupby(target)[value]
    k = g.size()
    n, N = len(k), int(k.sum())
    if n < 2 or N <= n:          # нечего оценивать
        keys = ("icc1", "icc1k", "k0", "ceiling")
        return dict.fromkeys(keys, np.nan)
    means, grand = g.mean(), long[value].mean()
    ssb = float((k * (means - grand) ** 2).sum())
    dev = long[value] - long[target].map(means)
    ssw = float((dev ** 2).sum())
    msb, msw = ssb / (n - 1), ssw / (N - n)
    k0 = (N - float((k ** 2).sum()) / N) / (n - 1)
    den = msb + (k0 - 1) * msw
    icc1 = (msb - msw) / den if den > 0 else np.nan
    icc1k = (msb - msw) / msb if msb > 0 else np.nan
    ceiling = float(np.sqrt(max(icc1k, 0))) if msb > 0 else np.nan
    return {"icc1": icc1, "icc1k": icc1k, "k0": k0,
            "ceiling": ceiling}
```

`long` — таблица действительных оценок: строка на оценку, столбец ролика и столбцы баллов. Готовые библиотечные функции ICC здесь не подходят: они ждут, что все ролики оценены одними и теми же наблюдателями.

## 13. Частые ошибки

| Ошибка | Чем плоха |
| --- | --- |
| Русская «Р» вместо латинской `R` в части кодов | один человек распадается на два кода, ролик остаётся без самооценки или без оценок |
| Столбцы `s01` … `s10` не в порядке строк карты | ключи перекодировки попадают не на те строки, метки обессмысливаются |
| Пропуск записан как 4 (карта) или 3 (утверждения) | середина шкалы вместо «нет ответа» |
| Самооценка усреднена с оценками наблюдателей | смешаны две разные мишени; модель учится не тому, что AMLAI 1.0 |
| Оценка удалена за расхождение с другими | метка подгоняется под большинство, разброс исчезает из данных |
| Наблюдатель исключён по одному признаку | теряются честные строгие или мягкие оценки |
| Разбиение по отрезкам или по оценкам, а не по людям | один человек и в обучении, и в тесте |
| Тест или части переразбиты в новой версии набора | тестовые ролики оказываются в обучении |
| Разметка до добора оценок | ролики с одной оценкой выпадают, а потом всё пересчитывается |
| Таблицы отредактированы вручную после подсчёта контрольных сумм | разработчик получает не то, что проверено |
