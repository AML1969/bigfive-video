# Как обучить AMLAI 2.0 на своём наборе роликов

Инструкция — для разработчика, который получил размеченный набор: ролики, собранные по документам 0–3 этой папки, и таблицу меток, подготовленную по [документу 5](5_Как_разметить_набор.md). В ней — как получить из набора модель AMLAI 2.0 и как проверить, что на русской речи она лучше нынешних моделей.

**Что такое AMLAI 2.0.** Та же модель, что AMLAI 1.0: те же кодировщики (CLIP для лица, CLAP для голоса, EmoRoBERTa для текста), то же описание поведения от локальной модели `qwen2.5vl:7b` и та же графовая модель слияния. Меняются данные: вместо англоязычного First Impressions V2 — наши русскоязычные ролики и средние оценки наших наблюдателей. На выходе — пять файлов весов (продукт усредняет их так же, как пять файлов AMLAI 1.0), отчёт о точности и решение, заменять ли AMLAI 1.0.

> **Код для нашего набора — четыре скрипта в папке `training/`:** `ru_labels.py`, `ru_extract.py`, `ru_train.py`, `ru_eval.py` (раздел 4). Код, которым обучали AMLAI 1.0 (`mm_extract.py`, `mm_train.py`), читает только First Impressions V2 и здесь не используется. Модель, кодировщики и нарезку роликов новые скрипты берут из кода продукта. Проверены они пока только на искусственных данных (`tests/test_ru_labels.py`, `tests/test_ru_training.py`): первый прогон на настоящих роликах — пробный набор, о котором сказано ниже.

## Коротко о главном

1. Убедитесь, что набор размечен по документу 5: в `labels.csv` есть метки, тест (15–20%) и пять частей.
2. Прочитайте, что делают четыре скрипта (раздел 4), и прогоните их на пробном наборе.
3. Один раз пройдите по всем роликам: признаки каждого 20-секундного отрезка и заодно оценки AMLAI 1.0. Отдельно — оценки OCEAN-AI.
4. Обучите два варианта: дообучение AMLAI 1.0 и обучение с нуля. Каждый — пять раз, по разу на каждую часть.
5. Выберите вариант по оценкам на пяти частях, не глядя на тест.
6. Один раз посчитайте точность на тесте и сравните с AMLAI 1.0, OCEAN-AI и постоянным ответом (раздел 7).
7. Если AMLAI 2.0 лучше, подключите её к продукту — это отдельная задача (раздел 10).

Сначала пройдите все шаги на пробном наборе из 20–30 роликов (памятка, раздел 11), чтобы отладить скрипты. На числа точности пробы не смотрите: роликов слишком мало.

## 1. Что нужно до начала

- **Набор.** Папка версии набора, например `ru_set_v1`, собранная по документу 5 (раздел 10): копии роликов `work/` без начала с листом ([памятка](0_Памятка_организатору.md), раздел 4), таблица меток `labels.csv`, таблицы оценок и файл `checks.md` с надёжностью меток. Обучайте на копиях, а не на оригиналах: лист с кодом в начале оригинала попадёт в распознанный текст и в описание поведения.
- **Компьютер.** Тот же, что для запуска BS Profiler 3.1 (раздел «Требования» в [README](../../README.md)): видеокарта NVIDIA с 24 ГБ памяти, установленный проект, запущенная Ollama с моделью `qwen2.5vl:7b`. Веса AMLAI 1.0 лежат в `~/bs/mm_runs_seeds/`: они нужны и для дообучения, и для сравнения. Не перезаписывайте их — всё новое кладите в отдельные папки.
- **Время.** Проход по роликам занимает примерно столько же, сколько длятся сами ролики. На девяти русских роликах полный анализ продукта моделью AMLAI 1.0 (вместе с эмоциями, голосом и мимикой) занимал от 0,75 до 1,15 длительности ролика; проход только моделью — не дольше. 400 роликов по 9 минут — около 60 часов, то есть 2,5–3 суток без перерыва. OCEAN-AI работает быстрее, примерно 0,4 длительности. Само обучение быстрое: один запуск AMLAI 1.0 на 6000 клипах First Impressions V2 занимал от 3 до 8 минут.
- **Диск.** Признаки занимают мало: около 22 КБ на отрезок, на 400 роликов — около 0,3 ГБ. Нарезки отрезков временные и удаляются после каждого ролика. Копии роликов можно читать с диска Windows по пути `/mnt/c/...` или `/mnt/d/...`: переносить их в WSL не обязательно.

## 2. Метки

Метки считает разметка (документ 5, разделы 5–7). Что из этого важно обучению:

1. Основная метка — среднее действительных оценок наблюдателей по каждой черте и по вопросу о собеседовании, в шкале 0…1: модель учится впечатлению, как и AMLAI 1.0.
2. Самооценка лежит отдельными столбцами `self_*` и в метку не входит; с ней только сравнивают (раздел 8).
3. В таблице нет роликов, у которых меньше двух действительных оценок, — их уже исключила разметка; не возвращайте их.
4. Если наблюдатели смотрели не весь ролик, а трёхминутный отрывок (памятка, раздел 6), метка всё равно описывает того же человека: обучайте на всех отрезках ролика.

Таблица `labels.csv`, одна строка на ролик:

| Столбец | Что в нём |
| --- | --- |
| `video_name` | код ролика, он же имя копии без `.mp4` |
| `openness` | открытость: среднее наблюдателей, 0…1 |
| `conscientiousness` | добросовестность, 0…1 |
| `extraversion` | экстраверсия, 0…1 |
| `agreeableness` | доброжелательность, 0…1 |
| `non-neuroticism` | эмоциональная устойчивость, 0…1 |
| `interview` | вопрос о собеседовании, 0…1 |
| `n_ratings` | число действительных оценок |
| `self_openness` … `self_non-neuroticism` | самооценка по 50 утверждениям, 0…1, — только для анализа |
| `sd_openness` … `sd_non-neuroticism` | разброс оценок наблюдателей по ролику — только для анализа |
| `cluster` | кластер знакомства из `videos.csv` |
| `split` | `train` или `test` (раздел 3) |
| `fold` | номер части от 1 до 5; у тестовых роликов пусто |

Имена черт — как в First Impressions V2 (эмоциональная устойчивость там называется `non-neuroticism`): так таблицу без переделок читает `training/evaluate.py`.

**Надёжность меток и потолок модели** по каждой черте уже посчитаны при разметке и записаны в `checks.md` набора (документ 5, раздел 8). Перенесите их в свой отчёт: без этих чисел нельзя понять, отчего точность низкая — от модели или от меток.

## 3. Разбиение роликов

Разбиение сделано при разметке (документ 5, раздел 9) и пришло в `labels.csv` столбцами `split` и `fold`. Правила, на которых оно держится и которые нельзя нарушать при обучении:

- **Делите по людям, а не по отрезкам.** Все отрезки одного ролика — в одной части. Если у человека два принятых ролика, оба идут в одну часть.
- **Тест** — 15–20% роликов (60–80 из 400). Он выбран один раз, случайно, с записанным начальным числом генератора. До раздела 8 на тестовые ролики не смотрите: ни оценок, ни подбора параметров, ни калибровки.
- **Остальные ролики — пять частей** примерно поровну. Каждая часть по очереди служит проверочной, а модель учится на остальных четырёх. Так каждый ролик получает оценку от модели, которая его не видела.
- **Кластеры.** Если кластеров много (шесть и больше примерно равных), в тест и в части идут целые кластеры: в тест — столько, чтобы набрать 15–20% роликов, остальные — по пяти частям, в каждой не меньше одного кластера; тогда модель не сможет опираться на общие для группы комнату, камеру и манеру съёмки. Если кластеров меньше шести, люди распределены случайно.
- **Разбиение не меняется.** Все варианты модели сравниваются на одних и тех же частях, а в новой версии набора старые ролики остаются в своих частях (документ 5, раздел 10).

## 4. Скрипты

Все четыре запускаются из `bs3-studio` командой `~/bs/venv/bin/python -m training.<имя> --help`.

| Скрипт | Что делает | Главные параметры |
| --- | --- | --- |
| `training/ru_labels.py` | разметка: `labels.csv` и таблицы проверок из трёх таблиц набора (документ 5) | `--set`, `--prev`, `--seed`, `--force` |
| `training/ru_extract.py` | проход по роликам: признаки отрезков и оценки AMLAI 1.0 | `--videos`, `--labels`, `--out`, `--limit` |
| `training/ru_train.py` | обучение на отрезках с метками роликов, одна часть за запуск | `--data`, `--labels`, `--fold`, `--out`, `--init`, `--lr` |
| `training/ru_eval.py` | оценки роликов, метрики с интервалами, сравнение с соперниками | `--mode`, `--ckpt`, `--ckpt-pattern`, `--oceanai` |

### ru_extract.py: признаки — тем же путём, что в продукте

Почему не `training/mm_extract.py`. Он берёт тексты из готовых таблиц First Impressions V2: расшифровки речи (Rev) и описания поведения от другой модели, Qwen3-VL-4B, по всему клипу. В продукте тексты получаются иначе: речь распознаёт Whisper, русский текст переводится на английский моделью Helsinki-NLP `opus-mt-ru-en`, а поведение описывает `qwen2.5vl:7b` по 16 кадрам отрезка. AMLAI 1.0 обучена на одних входах, а работает на других. AMLAI 2.0 нужно учить ровно на том, что она получит в продукте, поэтому признаки считает сам код продукта.

Как это сделано:

1. Нарезку и распознавание речи делает `LongVideoAnalyzer` из `bs3/longvideo.py`, тот же, что в продукте: отрезки по 20 секунд, хвост короче 6 секунд приклеивается к предыдущему отрезку, текст отрезка берётся из распознавания всего ролика.
2. Признаки отрезка считает `MMBackend` из `bs3/backend_mm.py` с языком `ru` и весами AMLAI 1.0. Его метод `_score` получает ровно вход модели для одного отрезка — словарь «модальность → вектор». В скрипте переопределите `_score`: сохранить вход и вызвать исходный метод.
3. Удачные отрезки в `timeline` результата идут в том же порядке, что сохранённые входы: i-й вход — это i-й отрезок, у которого есть `scores`. Отрезок без лица или без речи AMLAI 1.0 не пропускает: без найденного лица в CLIP идут целые кадры (`bs3/mm/faces.py`), без речи текстовая ветка получает пустую строку. Отрезок выпадает лишь при сбое — кадры не прочитались, пустой звук, не хватило памяти видеокарты, не ответила вовремя Ollama, — поэтому сами ничего не отбирайте: берите ровно те отрезки, у которых есть `scores`.

Сердце скрипта — наследник `MMBackend`, который запоминает вход модели после удачного прохода:

```python
from bs3.backend_mm import MMBackend, MMConfig
from bs3.longvideo import LongVideoAnalyzer


class CaptureMM(MMBackend):
    """AMLAI 1.0, которая запоминает вход модели."""

    def __init__(self, cfg):
        super().__init__(cfg)
        self.inputs = []

    def _score(self, batch):
        out = super()._score(batch)
        x = {m: v[0].cpu() for m, v in batch.items()}
        self.inputs.append(x)
        return out


be = CaptureMM(MMConfig(lang="ru")).load()
an = LongVideoAnalyzer(be, lang="ru")

# для каждого ролика — новая пустая временная папка
be.inputs.clear()
res = an.analyze(video, tmp_dir)
ok = [t for t in res["timeline"] if t.get("scores")]
assert len(ok) == len(be.inputs)
```

Что сохраняется по каждому ролику (`features/<код>.pt`):

- признаки отрезков: по каждой модальности матрица «отрезки × признаки» (`face` — 1024 числа, `audio`, `text` и `behavior` — по 1536), начало и конец каждого отрезка;
- оценки AMLAI 1.0 по отрезкам и по ролику (`res["scores"]`) — готовое сравнение с нынешней моделью;
- тексты отрезков: русскую речь и описание поведения (`res["timeline"]`).

Так он и работает:

- одна программа на все ролики: модели загружаются один раз;
- готовый ролик при повторном запуске пропускается — прерванный проход можно продолжить; сбой на одном ролике записывается в `extract_failed.txt`, и проход идёт дальше;
- для каждого ролика — новая пустая временная папка, иначе `analyze` взял бы описания поведения из файла `timeline.json` прошлого ролика; после сохранения признаков папка удаляется;
- в конце пишется `amlai1_scores.csv` — оценки AMLAI 1.0 по роликам, готовый соперник для раздела 7.

### ru_train.py: обучение

Основа — `training/mm_train.py`: та же модель (`PersonalityFusionModel`), та же функция потерь (средняя абсолютная ошибка), тот же оптимизатор Adam. Отличия:

- **Примеры — отрезки, метка — у ролика.** Каждый отрезок получает метку своего ролика. Чтобы длинные ролики не весили больше коротких, умножайте ошибку отрезка на 1 / (число отрезков ролика).
- **Части.** Параметр `--fold k`: проверочная часть — k, обучение — остальные четыре. Тестовые ролики скрипт не читает вовсе: `mm_train.py` в конце каждого запуска считает тест, а здесь так делать нельзя.
- **Проверка — по роликам.** На проверочной части оценки отрезков усредняются с весом по длительности, как в продукте, и уже по роликам считается CCC. По среднему CCC пяти черт выбирается лучшая эпоха и делается ранняя остановка (почему не mACC — раздел 7).
- **Дообучение.** Параметр `--init`: начальные веса из файла AMLAI 1.0. Модальности и шесть выходов (пять черт и собеседование) у нас те же, поэтому веса загружаются без изменений.
- **Формат результата** — как у `mm_train.py`: `best.pt` с ключами `state_dict`, `config`, `modalities`, `targets`, `epoch`, `dev`, поэтому продукт загружает новые веса без доработок. Рядом — `val_pred.csv`, оценки проверочной части по роликам (из них складываются оценки «вне части», раздел 6), и `result.json`.

### ru_labels.py и ru_eval.py

- `ru_labels.py` — разметка по документу 5: из `videos.csv`, `self.csv` и `ratings.csv` делает `labels.csv`, `ratings_scored.csv`, `self_scored.csv`, `raters.csv`, `exclusions.csv` и `checks.md` с надёжностью меток. Готовый `labels.csv` он не перезаписывает (нужен `--force`). Для новой версии набора он получает `labels.csv` прежней версии параметром `--prev`: `split` и `fold` старых роликов берутся из него, распределяются только новые (документ 5, раздел 10).
- `ru_eval.py` — оценки роликов из сохранённых признаков (среднее отрезков с весом по длительности; несколько файлов весов усредняются, как в продукте) и метрики по каждой черте: CCC, корреляция Пирсона, ACC = 1 − средняя ошибка, с 95-процентными интервалами бутстрепом по роликам. Он же сравнивает с соперниками раздела 7 — `--mode test` на тесте, `--mode oof` на оценках «вне части» — и печатает таблицу с разницей к AMLAI 2.0 и её интервалом.

## 5. Проход по роликам

Команды ниже — для скриптов из раздела 4; пути к набору — для примера. Пробный запуск прохода — с `--limit 5`. Если набор пришёл без `labels.csv`, сначала разметьте его скриптом `ru_labels.py` по документу 5 (он пишет `labels.csv` и таблицы проверок в папку набора). Готовый `labels.csv` не пересчитывайте: разбиение в нём уже сделано (раздел 12).

```bash
cd bs3-studio
# только если в папке набора нет labels.csv
~/bs/venv/bin/python -m training.ru_labels --set /mnt/d/ru_set_v1
# проход по роликам
~/bs/venv/bin/python -m training.ru_extract \
  --videos /mnt/d/ru_set_v1/work \
  --labels /mnt/d/ru_set_v1/labels.csv --out ~/data/ru_v1
```

Проход идёт несколько суток: запускайте его в фоне с записью журнала (например, через `nohup`) и на это время не запускайте анализы в веб-версии — видеокарта одна. После первых пяти роликов проверьте:

- [ ] число отрезков ролика — примерно длительность в секундах, делённая на 20;
- [ ] у каждого отрезка есть описание поведения на английском, почти у каждого — русский текст речи (пустой текст — пауза между вопросами);
- [ ] отрезков без `scores` (сбой анализа) — единицы, а не десятки.

OCEAN-AI считается уже готовой командой продукта, по одному ролику за запуск. Нужны оценки всех роликов, а не только тестовых: по нетестовым подбирается калибровка (раздел 7).

```bash
mkdir -p ~/data/ru_v1/oceanai
for f in /mnt/d/ru_set_v1/work/*.mp4; do
  n=$(basename "$f" .mp4)
  ~/bs/venv/bin/bs3 infer "$f" --backend oceanai \
    --out ~/data/ru_v1/oceanai/$n.json
  rm -rf ~/data/ru_v1/oceanai/$n
done
```

Команда `rm -rf` удаляет папку с нарезками отрезков (`<имя ролика>/segments`), которую `bs3 infer` оставляет рядом с файлом результата. По одному ролику удобнее: прерванный проход продолжается с того ролика, на котором остановился, а результаты лежат по одному файлу на ролик.

## 6. Обучение

Два варианта, оба на одних и тех же пяти частях.

**Вариант А — дообучение AMLAI 1.0.** Начальные веса — пять файлов AMLAI 1.0: для части 1 — `seed1`, для 2 — `seed2`, для 3 — `seed3`, для 4 — `seed4`, для 5 — `seed42`. Шаг обучения в 10 раз меньше, чем у 1.0, — `1e-5`; второй запуск — с шагом `3e-5`. Остальное как у 1.0: пакет 32, до 100 эпох, остановка после 15 эпох без улучшения.

- плюс: на 300–400 роликах это обычно точнее — модель начинает не с нуля;
- минус: веса происходят от First Impressions V2 и, скорее всего, наследуют его условие «только некоммерчески» (раздел 11).

```bash
S=(seed1 seed2 seed3 seed4 seed42)
for k in 1 2 3 4 5; do
  ~/bs/venv/bin/python -m training.ru_train \
    --data ~/data/ru_v1 --labels /mnt/d/ru_set_v1/labels.csv \
    --fold $k --seed $k --lr 1e-5 \
    --init ~/bs/mm_runs_seeds/${S[k-1]}/best.pt \
    --out ~/bs/amlai2_runs/A_lr1e-5/fold$k
done
```

**Вариант Б — с нуля.** Случайные начальные веса и рецепт 1.0 без изменений: шаг `1e-4`, пакет 32, отсев 0,15, остановка после 15 эпох без улучшения. Команда та же, без `--init`, с `--lr 1e-4` и своей папкой, например `~/bs/amlai2_runs/B_lr1e-4/fold$k`.

- плюс: модель не зависит от First Impressions V2;
- минус: роликов в 15–20 раз меньше, чем клипов в обучающей части First Impressions V2 (300–400 против 6000), поэтому точность, вероятно, будет ниже.

**Как выбрать вариант.** Для каждого варианта соберите оценки «вне части»: каждый нетестовый ролик оценивает модель той части, где он был проверочным. По этим оценкам посчитайте CCC каждой черты сразу на всех нетестовых роликах — по одному числу на черту для каждого варианта; оно устойчивее, чем среднее по пяти частям. Выигрывает вариант с наибольшим средним CCC пяти черт. Это число годится для выбора варианта, но не как итоговая точность: лучшая эпоха каждой модели выбиралась по той же части, поэтому оно немного завышено; честное число даёт только тест (раздел 8). Рядом посчитайте то же для соперников из раздела 7: если ни один вариант их не обгоняет, обучение не помогло.

```bash
~/bs/venv/bin/python -m training.ru_eval --mode oof \
  --data ~/data/ru_v1 --labels /mnt/d/ru_set_v1/labels.csv \
  --ckpt-pattern "~/bs/amlai2_runs/A_lr1e-5/fold{fold}/best.pt" \
  --out ~/data/ru_v1/eval_oof_A.json
```

Правила:

- меняйте одну вещь за раз и сравнивайте на тех же частях;
- вариантов — несколько, а не десятки: при 300–400 роликах выбор лучшего из многих даёт выигрыш, который на тесте исчезнет;
- собеседование считайте отдельно и в выбор не включайте, как у AMLAI 1.0.

**AMLAI 2.0 — это пять моделей пяти частей выбранного варианта.** Продукт усредняет их, как пять файлов AMLAI 1.0; отдельно переобучать на всех данных не нужно.

## 7. Как сравнивать и читать числа

**CCC — главная мера.** Он учитывает и связь оценок с меткой, и совпадение шкалы. Корреляция Пирсона показывает только связь; смотрите на обе.

**mACC льстит.** mACC — это 1 минус средняя ошибка. На тесте First Impressions V2 постоянный ответ «всем среднее» (средняя метка обучающей части) даёт mACC 0,8815, а AMLAI 1.0 — 0,9202. Средние оценки наших наблюдателей теснятся к середине шкалы ещё сильнее (памятка, раздел 9), поэтому у постоянного ответа mACC будет ещё выше. Всегда печатайте рядом mACC постоянного ответа.

С чем сравнивать:

| Соперник | Что это |
| --- | --- |
| Постоянный ответ | средняя метка обучающих роликов, одна на всех |
| AMLAI 1.0 | оценки из прохода (раздел 5) как есть |
| AMLAI 1.0 с калибровкой | те же оценки, приведённые к нашей шкале |
| OCEAN-AI | оценки из прохода как есть |
| OCEAN-AI с калибровкой | так же, приведённые к нашей шкале |

**Калибровка** — по каждой черте прямая a·x + b, у которой среднее и разброс откалиброванных оценок совпадают со средним и разбросом метки: a = sd(метка) / sd(оценка), b = среднее(метка) − a·среднее(оценка). Подбирается по нетестовым роликам: при сравнении по частям — на четырёх обучающих частях и применяется к пятой, для теста — на всех нетестовых роликах. Такая прямая даёт сопернику наибольший возможный CCC — он равен корреляции Пирсона; прямая по наименьшим квадратам его занижает (при r = 0,5 даёт 0,40 вместо 0,50). Без калибровки сравнение нечестное: шкалы у моделей разные (на русских роликах AMLAI 1.0 обычно даёт 0,3–0,45, OCEAN-AI — 0,65–0,80), и CCC у них занижен одним только сдвигом шкалы. Если AMLAI 2.0 не обгоняет AMLAI 1.0 с калибровкой, обучение дало только перевод шкалы.

**Потолок.** Модель не может коррелировать с меткой сильнее, чем корень из надёжности метки: при надёжности 0,36 это 0,60, при 0,64 — 0,80 (памятка, раздел 9). Пишите потолок рядом с результатом каждой черты.

**Интервалы.** На 60–80 тестовых роликах 95-процентный интервал корреляции — примерно ±0,2: разница меньше этого — ещё не разница. Интервал разницы двух моделей считайте бутстрепом по роликам, на одних и тех же выборках роликов для обеих моделей.

**Ориентир.** AMLAI 1.0 на тесте First Impressions V2 (1997 клипов, среднее пяти файлов весов): CCC открытости 0,69, добросовестности 0,78, экстраверсии 0,76, доброжелательности 0,61, эмоциональной устойчивости 0,73, собеседования 0,76. С нашими числами это напрямую не сравнивается: другие ролики и другие метки.

## 8. Тест — один раз

1. Зафиксируйте выбранный вариант: пять файлов `best.pt` скопируйте в `~/bs/amlai2/v1/fold1/` … `fold5/`. Дальше в нём ничего не меняйте.
2. Посчитайте оценки тестовых роликов из сохранённых признаков (`ru_eval.py`): у AMLAI 2.0 — среднее пяти моделей, как в продукте. Тем же запуском — всех соперников из раздела 7, с калибровкой по нетестовым роликам.

   ```bash
   ~/bs/venv/bin/python -m training.ru_eval --mode test \
     --data ~/data/ru_v1 --labels /mnt/d/ru_set_v1/labels.csv \
     --ckpt "~/bs/amlai2/v1/fold*/best.pt" \
     --oceanai ~/data/ru_v1/oceanai \
     --out ~/data/ru_v1/eval_test.json
   ```

   Каждого соперника скрипт сравнивает с AMLAI 2.0 только на тех роликах, где есть оценки обоих (пропуски ничем не заполняются), и печатает это число роликов. Тестовый ролик без файла признаков останавливает расчёт: разберитесь, почему проход его пропустил, или сознательно передайте `--allow-missing`.

3. Проверьте, что продукт даёт то же самое. Прогоните 3–5 тестовых роликов через `bs3 infer` с новыми весами, по одному ролику за запуск:

   ```bash
   ~/bs/venv/bin/bs3 infer /mnt/d/ru_set_v1/work/R0147.mp4 \
     --mm-ckpt "~/bs/amlai2/v1/fold*/best.pt" \
     --out ~/data/ru_v1/check/R0147.json
   ```

   Кавычки вокруг пути к весам нужны: звёздочку и `~` раскрывает сама программа. Папку `R0147` с нарезками рядом с файлом результата потом удалите. Оценки должны совпасть с оценками `ru_eval.py` с точностью до нескольких сотых: описание поведения Ollama пишет заново, и оно немного отличается от сохранённого. Большее расхождение означает, что признаки при обучении считались не так, как в продукте.

4. Решение:
   - **AMLAI 2.0 лучше**, если средний CCC пяти черт на тесте выше, чем у AMLAI 1.0 с калибровкой и у OCEAN-AI с калибровкой, и 95-процентный интервал разницы целиком выше нуля;
   - **разница не доказана**, если она положительная, но интервал задевает ноль: на 60–80 роликах это обычный исход; тогда решает владелец проекта, в том числе с учётом лицензии (раздел 11);
   - **хуже** — к продукту не подключать; проверьте надёжность меток и долю пропущенных отрезков.
5. Когда тест открыт, параметры по нему больше не подбирайте. Если после теста что-то поменяли, нужен новый тест — на новых роликах.
6. Дополнительно посчитайте связь оценок AMLAI 2.0 с самооценкой по каждой черте. Ожидайте 0,1–0,3 (памятка, раздел 9); для выбора модели это число не используется.
7. Посмотрите, какие типы MBTI выходят у AMLAI 2.0 на тесте. Продукт переводит черты в тип с границей 0,5, а шкала у новой модели своя. Если почти все ролики попадают в один тип или в «X», это нужно описать в оговорках продукта.

## 9. Паспорт модели

Рядом с весами положите файл `MODEL.md`:

- набор: имя версии (например, `ru_set_v1`), его файл `SHA256SUMS` и паспорт набора из его `README.md` (документ 5, раздел 10): число роликов в обучении и в тесте, число оценок на ролик;
- код: коммит репозитория и параметры выбранного варианта;
- надёжность меток и потолок по каждой черте;
- результаты по частям и на тесте, с интервалами, рядом с соперниками;
- исключённые ролики и оценки с причинами.

Не кладите в git ролики, тексты отрезков, описания поведения, признаки и метки: это персональные данные участников. Публиковать ли веса, решает владелец проекта.

## 10. Подключение к продукту

Проверить новые веса можно без правок кода — командой из раздела 8. Чтобы AMLAI 2.0 появилась на странице, нужна отдельная доработка. Главные места:

- `bs3/__init__.py` — новая модель в `MODEL_TITLES` (например, ключ `mm2` и название «AMLAI 2.0») и в `MODALITIES`; какая модель будет по умолчанию (`DEFAULT_MODEL`), решает владелец проекта;
- `bs3/settings.py` — путь к весам по образцу `MM_CHECKPOINTS`; веса AMLAI 1.0 не трогайте;
- `bs3/pipeline.py` и `bs3/cli.py` — выбор весов по ключу модели: код модели тот же (`MMBackend`), меняется только путь к весам;
- тексты, где названа модель и её данные: `bs3/narrative.py`, `bs3/web/parts.py` и `bs3/pdf/frames.py` («обученная на First Impressions V2»), `bs3/caveats.py`, `bs3/labels.py`; условия вида «объяснения есть только у AMLAI 1.0» привязаны в коде к ключу `mm`;
- данные обучения, записанные по ключу модели без её названия: `bs3/pdf/fmt.py` (словарь `TRAINED_ON` — добавьте запись для нового ключа) и `bs3/report.py` (поля `trained_on` и `scale`: всё, что не OCEAN-AI, записывается как FIV2); все такие места — командой `grep -rlE "First Impressions V2|FIV2" bs3`;
- тесты: название «AMLAI 1.0» встречается в десятках файлов пакета и тестов — найдите их командой `grep -rl "AMLAI 1.0" bs3 tests`;
- `README.md` пакета (`bs3-studio`) — «Требования», «Установка с нуля» (путь к весам), «Где что лежит» и «Оговорки» (модели и их шкалы); `README.md` в корне репозитория — таблица «Точность» и раздел «Данные и веса, которых нет в репозитории».

- AMLAI 1.0 обучена на First Impressions V2, а его лицензия CC BY-NC 4.0 разрешает только некоммерческое использование. Вариант А начинается с весов AMLAI 1.0 и, скорее всего, наследует это ограничение. Вариант Б учится только на нашем наборе и от First Impressions V2 не зависит.
- У кодировщиков и моделей, через которые проходят данные, свои лицензии: CLIP и Whisper — MIT; CLAP, `qwen2.5vl:7b` и поиск лица MediaPipe — Apache-2.0; перевод `opus-mt-ru-en` — CC BY 4.0; у EmoRoBERTa явной лицензии нет. Для продажи продукта это нужно проверить отдельно — даже у варианта Б.

## 12. Частые ошибки

| Ошибка | Чем плоха |
| --- | --- |
| Один человек и в обучении, и в тесте; деление по отрезкам вместо роликов | точность на тесте завышена |
| Параметры, калибровка или выбор варианта по тесту | то же |
| Самооценка вместо оценок наблюдателей или их среднее | модель учится другому, чем AMLAI 1.0, и сравнение теряет смысл |
| Признаки посчитаны не тем путём, что в продукте (например, `training/mm_extract.py` с готовыми текстами) | в продукте модель получит другие входы, чем при обучении |
| Обучение на оригиналах | лист с кодом попадает в текст и в описание поведения |
| mACC без постоянного ответа рядом | высокое число при бесполезной модели |
| Новые веса записаны в `~/bs/mm_runs_seeds/` | продукт молча начнёт работать на непроверенных весах |
| Одна временная папка на разные ролики в `ru_extract.py` | описание поведения берётся из чужого ролика |
| Метки или разбиение пересчитаны по-своему, минуя документ 5 | две версии меток одного набора; тестовые ролики могут попасть в обучение |

## 13. Что можно попробовать потом

Когда AMLAI 2.0 уже работает, каждую идею проверяйте отдельно и на тех же частях:

- **Русский кодировщик текста** вместо перевода на английский и EmoRoBERTa: при переводе часть смысла речи теряется. Понадобятся правки в `bs3/mm/extractors.py` и `bs3/backend_mm.py`, а признаки текста придётся посчитать заново.
- **Больше оценок на ролик** — самый сильный рычаг: надёжность меток растёт с числом оценок (памятка, раздел 6), а с ней и потолок модели.
- **Отдельная модель на самооценке** — и отдельное решение, как её показывать: самооценка отвечает на другой вопрос, чем впечатление наблюдателей.
